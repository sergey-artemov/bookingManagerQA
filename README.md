# Booking Manager QA

Пет-проект для отработки полного QA-цикла: **требования → ручное тестирование → баг-репорты → фиксы → автотесты (API + БД)**.

Сервис бронирования номеров отеля. REST API поверх PostgreSQL, запуск в Docker.

## Бизнес-правила (требования)

| №  | Правило                                                                                                         |
|----|-----------------------------------------------------------------------------------------------------------------|
| 1  | Номер комнаты обязателен, целое число в диапазонах: 101–150, 201–250, 301–350, 401–450, 501–550                 |
| 2  | Дата начала бронирования (bookedFrom) обязательна                                                               |
| 3  | Дата окончания бронирования (bookedTo) обязательна                                                              |
| 4  | Даты начала и окончания — не ранее текущей даты                                                                 |
| 5  | Дата начала бронирования должна быть меньше даты окончания                                                      |
| 6  | ФИО гостя обязательно, не более 100 символов                                                                    |
| 7  | Комментарий опционален, не более 200 символов                                                                   |
| 8  | Один номер не может быть забронирован дважды на пересекающиеся даты  |

Формат дат в API: ISO (`YYYY-MM-DD`).

## Технологии

- Java 17, Spring Boot 3.5.x (Web, Data JPA, Validation)
- PostgreSQL 15 (Docker, docker-compose)
- Flyway — миграции и начальные тестовые данные
- Lombok
- Тесты: JUnit 5, Rest Assured, Testcontainers (в планах — см. Roadmap)

## Запуск

```bash
# 1. Поднять базу (и pgAdmin: http://localhost:5050)
docker compose up -d

# 2. Собрать и запустить приложение
mvn spring-boot:run
```

Приложение: `http://localhost:8080`. Подключение к БД: `localhost:5432`, база `bookingsdb`, пользователь `user`, пароль `pass`.

## API

| Метод | Путь                  | Описание            | Успешный ответ |
|-------|-----------------------|---------------------|----------------|
| GET | `/api/bookings`       | Список всех броней  | 200 |
| GET | `/api/bookings/{id}`  | Бронь по id         | 200 / 404 |
| POST | `/api/bookings/new`  | Создать бронь       | 201 / 400 |
| PUT | `/api/bookings/{id}`  | Обновить бронь      | 200 / 400 / 404 |
| DELETE | `/api/bookings/{id}`  | Удалить бронь       | 204 / 404 |

Пример POST-запроса:

```json
{
  "roomNumber": 305,
  "bookedFrom": "2026-12-01",
  "bookedTo": "2026-12-05",
  "guestName": "Иванов Иван Иванович",
  "comment": "Поздний заезд"
}
```

## Тестирование

- Интеграционные тесты на JUnit 5 + Rest Assured. 
- Изолированная БД PostgreSQL в Docker-контейнере (Testcontainers).
- Миграции схемы — Flyway.
- Запуск: mvn test (контейнер поднимается и удаляется автоматически).

- E2E через реальный браузер (Selenide): создание брони через форму → проверка в списке и в БД → удаление с проверкой confirm-диалога и обеих веток (отмена/подтверждение). Требование окружения: Chrome, headless-режим по умолчанию. Браузеру тестов явно задаётся --lang=ru для совпадения с локалью пользователя
